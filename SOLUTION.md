## Решения

Матчи загружаются через `fetch(MATCHES_URL)`. Проверяю `response.ok` и наличие массива `matches`; для первого запроса показываю индикатор загрузки, при ошибке — сообщение и кнопку «Повторить», а для пустого массива — отдельное пустое состояние. Во время ручного обновления кнопка блокируется, а при ошибке уже показанные матчи и время последнего успешного обновления не сбрасываются.

Статус беру из ответа сервера, а не вычисляю по дате: `scheduled` отображается как «Запланирован», `live` — «Идёт», `finished` — «Завершён», `postponed` — «Перенесён». В фильтре «Предстоящие» показываю `scheduled` и `postponed`, потому что эти матчи ещё не завершены; в «Завершённые» — только `finished`; `live` остаётся только во «Все», так как матч уже начался, но ещё не закончен.

Дату форматирую через `Intl.DateTimeFormat`, поэтому используется часовой пояс устройства. Если `startsAt` равен `null` или дата некорректна, показываю «Дата уточняется». Счёт проверяю сравнением с `null`, поэтому результат `0:0` не теряется; `score: null` означает, что счёт показывать не нужно.

Избранное хранится в состоянии как массив id матчей. Выбор каждой карточки независим, сохраняется при переключении фильтров и повторной загрузке данных, но намеренно не сохраняется между запусками приложения.

Время последнего обновления меняю только после успешного ответа и передаю в `UpdatedAgo`, поэтому после обновления отсчёт начинается заново, а при ошибке продолжает считаться от последнего успешного запроса. При размонтировании экран игнорирует результат незавершённого запроса, чтобы не обновлять состояние закрытого компонента; для `FlatList` использую стабильный ключ `id`.

## Баги из части 2

1. Звёздочки: `Boolean(favorites.indexOf(id))` давал `true` для отсутствующего id, потому что `indexOf` возвращает `-1`, и `false` для первого элемента с индексом `0`. Кроме того, `push` и `splice` меняли тот же массив, поэтому React мог не увидеть новое состояние; исправил проверку на `includes` и сделал функциональное неизменяемое обновление массива.
2. «Обновлено N сек назад»: интервал замыкал начальное значение `seconds` и всегда пытался установить одно и то же число, а параметр `since` вообще не использовался; очистки интервала тоже не было. Теперь количество секунд вычисляется как разница между `Date.now()` и `since`, эффект перезапускается при изменении `since`, а интервал очищается через `clearInterval`.

## Как я использовал ИИ

Использовал ChatGPT и Codex для анализа исходного проекта, поиска причин двух багов, реализации отдельных этапов и подготовки сценариев проверки. Результат проверял через Git diff, TypeScript, сборку Expo Web и реальные браузерные сценарии: загрузку восьми матчей, фильтры 8/4/3, избранное, обновление, ошибки, пустой ответ, таймер и узкий экран.

Было два случая, когда результат ИИ пришлось уточнить. Первоначальная браузерная автоматизация не смогла подключиться к браузеру, поэтому я повторил проверку через локальный Microsoft Edge и DevTools-протокол и отдельно просмотрел скриншот. Одна из предложенных команд запуска также оказалась некорректной: Expo воспринял номер порта как путь к проекту; это было видно по ошибке `Invalid project root`, после чего команда была исправлена.
